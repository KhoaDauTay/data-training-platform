## Mở bài

Tìm `đỏ` ra ba sản phẩm: đèn lồng lụa đỏ, khăn lụa đỏ, đèn lồng Hội An đỏ lớn. Cái nào đứng đầu, và vì sao? Bài này tính tay con số `_score` mà máy in ra.

## Ý chính

Elasticsearch chấm điểm mỗi từ trong mỗi tài liệu bằng BM25, rồi cộng điểm các từ của câu tìm. Ba yếu tố:

- **IDF** (độ hiếm): `ln(1 + (N − n + 0.5) / (n + 0.5))`, với N là số tài liệu có trường đó, n là số tài liệu chứa từ. Từ hiếm, điểm cao.
- **TF** (số lần trong tài liệu, tf): càng nhiều lần càng cao, nhưng **bão hòa**: không bao giờ vượt quá k1 + 1 = 2,2 lần.
- **Độ dài**: tài liệu ngắn hơn độ dài trung bình (avgdl) được thêm điểm, tài liệu dài bị bớt, với b = 0,75.

Công thức Elasticsearch dùng: điểm = IDF × tf × 2,2 / (tf + 1,2 × (0,25 + 0,75 × dl / avgdl)), dl là số từ của tài liệu.

Tính tay `đỏ` trong tài liệu 1. Có 12 tài liệu, `đỏ` ở 3: IDF = ln(1 + 9,5 / 3,5) = ln 3,714 = 1,3122. Tổng số từ của 12 tên là 58, nên avgdl = 58 / 12 = 4,833. Tài liệu 1 có 4 từ, tf = 1: 2,2 / (1 + 1,2 × (0,25 + 0,75 × 4 / 4,833)) = 2,2 / 2,0448 = 1,0759. Điểm = 1,3122 × 1,0759 = 1,4118, đúng con số 1.4117621 máy in ra. Tài liệu 11 có 6 từ nên chỉ được 1,1943.

## Cú pháp

```text
score(word, doc) = IDF × TF
IDF = ln(1 + (N - n + 0.5)
           / (n + 0.5))
TF = tf × (k1 + 1) / (tf + k1
     × (1 - b + b × dl / avgdl))
k1 = 1.2   b = 0.75
```

- Câu tìm nhiều từ: cộng điểm từng từ.
- Máy tính bằng số thực 32 bit (float) như Lucene, nên chữ số cuối có thể lệch so với tính bằng máy tính bỏ túi.

## Lỗi hay gặp

Tưởng `_score` là phần trăm hay số lần khớp. Đó là một con số tương đối, chỉ so được giữa các kết quả của cùng một câu tìm trên cùng chỉ mục:

```json
// WRONG: scores of two searches
GET shop/_search
{"query": {"match": {
  "name": "đèn"}}}
```

```json
// FIX: compare hits of one search
GET shop/_search
{"query": {"match": {
  "name": "đèn đỏ"}}}
```

Gửi một số làm câu tìm cho trường chữ thì vẫn chạy, nhưng gửi một đối tượng thì bị từ chối:

```json
// ERROR parsing_exception
GET shop/_search
{"query": {"match": {
  "name": {"text": "đỏ"}}}}
```

## Thực hành

Ba bước: một từ phổ biến vừa, một từ hiếm, rồi hai từ cùng lúc (chấm cả thứ tự).

## Tóm tắt

- BM25 = IDF × TF, cộng qua các từ của câu tìm.
- Từ hiếm có IDF lớn; tài liệu ngắn được thêm điểm.
- TF bão hòa: lặp một từ không đẩy điểm lên mãi (tối đa 2,2 lần).
- `_score` chỉ so được trong cùng một câu tìm.

# EN

## Opening

Searching `đỏ` (red) finds three products: the red silk lantern, the red silk scarf and the large red Hoi An lantern. Which comes first, and why? This lesson works out by hand the `_score` the engine prints.

## Key idea

Elasticsearch scores each word in each document with BM25, then adds the scores of the search's words. Three factors:

- **IDF** (rarity): `ln(1 + (N − n + 0.5) / (n + 0.5))`, where N is the number of documents that have the field and n the number holding the word. A rare word scores high.
- **TF** (times in the document, tf): more is higher, but it **saturates**: never above k1 + 1 = 2.2 times.
- **Length**: a document shorter than the average length (avgdl) gains, a longer one loses, with b = 0.75.

The formula Elasticsearch uses: score = IDF × tf × 2.2 / (tf + 1.2 × (0.25 + 0.75 × dl / avgdl)), where dl is the document's word count.

Work out `đỏ` in document 1 by hand. There are 12 documents, `đỏ` is in 3: IDF = ln(1 + 9.5 / 3.5) = ln 3.714 = 1.3122. The 12 names hold 58 words in total, so avgdl = 58 / 12 = 4.833. Document 1 has 4 words, tf = 1: 2.2 / (1 + 1.2 × (0.25 + 0.75 × 4 / 4.833)) = 2.2 / 2.0448 = 1.0759. Score = 1.3122 × 1.0759 = 1.4118, the very 1.4117621 the engine prints. Document 11 has 6 words, so it only gets 1.1943.

## Syntax

```text
score(word, doc) = IDF × TF
IDF = ln(1 + (N - n + 0.5)
           / (n + 0.5))
TF = tf × (k1 + 1) / (tf + k1
     × (1 - b + b × dl / avgdl))
k1 = 1.2   b = 0.75
```

- A several-word search: add each word's score.
- The engine computes in 32-bit floats as Lucene does, so the last digit may differ from a pocket calculator.

## Common mistakes

Reading `_score` as a percentage or a match count. It is a relative number, comparable only between the hits of one search on one index:

```json
// WRONG: scores of two searches
GET shop/_search
{"query": {"match": {
  "name": "đèn"}}}
```

```json
// FIX: compare hits of one search
GET shop/_search
{"query": {"match": {
  "name": "đèn đỏ"}}}
```

Sending a number as the search text of a text field still runs, but sending an object is refused:

```json
// ERROR parsing_exception
GET shop/_search
{"query": {"match": {
  "name": {"text": "đỏ"}}}}
```

## Practice

Three steps: a fairly common word, a rare word, then two words at once (the order is graded too).

## Recap

- BM25 = IDF × TF, added over the search's words.
- A rare word has a large IDF; a short document gains.
- TF saturates: repeating a word cannot push the score up forever (2.2 times at most).
- `_score` is only comparable within one search.
